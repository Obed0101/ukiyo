### Renderer differences found by the pixel comparison, and their fixes

The first headless/browser comparison matched the simulation but not the pixels. Three causes, all fixed:

- **Text on half pixels.** `GameUi.Label` centered odd-width text on x.5 canvas pixels (1.5 screen pixels at 3×), which
  the CPU renderer sampled as jagged glyphs. Labels now start on whole canvas pixels.
- **three.js blended in gamma space.** A WebGL canvas blends the encoded sRGB values, against the contract ("straight
  alpha in linear space", [protocol](protocol.md)); a 0.92-alpha panel hid what the CPU renderer showed behind it. The
  adapter now draws into an `SRGB8_ALPHA8` target, where the GPU blends in linear as wgpu's `*Srgb` surface does, and
  copies it to the canvas.
- **three.js multisampled, the others do not.** `antialias: true` softened sprite edges and bled the neighboring
  atlas cell at tile seams. It is off, matching wgpu (`Multisample.Count = 1`) and the CPU renderer.
